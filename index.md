## Software Design and Engineering

<p>
<a href="https://github.com/briepeno/briepeno.github.io/tree/main/WeightTracking_README">
  Weight Tracking Application Project
</a></p>

<p>The artifact I selected for the software design and engineering category is a weight tracking Android application that I originally developed for CS 360: Mobile Architecture and Programming. The application was built using Java and Android Studio, with SQLite to store user information and weight records. The original version allowed users to create an account, add or delete weight entries, set a goal weight, view their history, and receive an SMS notification when they reached their goal.</p>

<p>I chose this artifact because there were several areas I wanted to improve, particularly how the application displayed information and how the code was organized. While the original version could store weight records, it did not provide much insight into the user's progress. I added a dashboard displaying the starting, current, and goal weights, along with total weight change, remaining weight, recent trends, and percentage of progress toward a goal. I also created a line chart to show weight changes over time. These additions made it easier for users to see their progress without having to compare individual entries.</p>

<p>I also wanted to improve the application's structure. In the original version, MainActivity was responsible for several different functions, including calculations, navigation, and updating the interface. As I added features, the code became harder to manage. I moved the validation, calculations, navigation, chart, and weight-record logic into separate classes. I strengthened input validation for weights, goals, usernames, passwords, and phone numbers and added tests for the calculations and validation rules. These changes demonstrate my ability to improve an existing application's design, organize code, and work with different Android components and a database.</p>

<p>One challenge I encountered was handling weight records in different orders. The history list displays the newest entries first, but the chart and progress calculations need the records in chronological order. I had to make sure each part of the application used the data correctly. I also learned that refreshing a RecyclerView, which displays the weight history, does not automatically retrieve updated records from the database. The adapter needed to reload the data before the changes would appear on the screen. This helped me better understand how the database, application logic, and interface interact.</p>

<p>Navigation was another issue. I wanted users to move between screens consistently, but at one point the Settings page would not open correctly. I also had to fix the dashboard so it displayed updated information whenever a user returned to it. Testing these problems showed me why it is important to check how the different parts of an application work together rather than testing each feature separately.</p>

<p>Cleaning up the code was more involved than I expected. Initially, I thought reducing repeated code would mean making everything shorter. Instead, I found that separating responsibilities into different classes was more useful. Some parts of the project became longer, but the code was easier to follow because each class handled a specific function. Moving the calculations and validation rules out of MainActivity also made them easier to test without involving the interface. I used the issues I found during testing to revise the application, particularly its navigation, validation, and data updates.</p>

<p>This enhancement addressed the course outcomes related to developing computing solutions, applying appropriate tools and techniques, and considering security. I used Java, SQLite, RecyclerView, SharedPreferences, and Android's SMS functionality to support the application's features. I also chose to build the line chart myself rather than add another library because I only needed a basic visualization. The progress calculations account for weight loss, weight gain, missing goals, and different amounts of weight history. I improved how the application handles invalid or missing information to prevent incorrect results and unexpected crashes.</p>

<p>One area I did not fully address was password security. Although I strengthened password requirements and input validation, passwords are still stored in plain text. I understand that this would not be acceptable in a production application and that passwords should be securely hashed. I considered adding this improvement but decided to stay within the scope of my planned enhancement. This is something I would address in a future version.</p>

<p>Overall, this enhancement gave me more experience working with an existing codebase and improving how its components are organized. I learned that adding features is only part of software development. Making sure those features work together, handling unexpected inputs, and keeping the code manageable are just as important. The application is more useful than the original version, and I have a better understanding of how to approach similar problems in future projects.</p>

## Algorithms and Data Structures

<p>
<a href="https://github.com/briepeno/briepeno.github.io/tree/main/AppointmentService_README">
  Appointment Services Project
</a></p>

<p>For my algorithms and data structures enhancement, I used the service application I created in CS 320: Software Testing, Automation, and Quality Assurance. The application manages contacts, tasks, and appointments, with separate classes for storing and validating each type of record. The original project used ArrayLists to store records and searched through them by ID whenever it needed to find one.</p>

<p>I chose this project because it gave me an opportunity to improve an application that already worked. The original search method had to check records one at a time, which could become inefficient as the list grew. For the enhancement, I replaced the ArrayList storage with a binary search tree (BST). I created one reusable BST class for contacts, tasks, and appointments, then updated the service classes to use it. The tree supports insertion, searching, deletion, and in-order traversal based on each record's unique ID. I also handled the different deletion cases, including nodes with no children, one child, or two children.</p>

<p>This project allowed me to apply concepts I had learned in CS 300 to a Java application. My earlier work with data structures was in C++, so using a BST in a different language helped me understand how those concepts transfer between projects. I also added JUnit tests for the tree to check insertion, duplicate IDs, searching, deletion, and traversal. After making the changes, I reran the original tests to make sure the new data structure did not break the existing functionality.</p>

<p>I also wanted to measure whether the BST actually improved performance. I tested both approaches using 10,000 records and 20,000 searches. The ArrayList search took 267.271 milliseconds, while the BST took 10.046 milliseconds. That made the BST approximately 26.60 times faster in my test. Both approaches successfully completed all 20,000 searches, so the change improved performance without affecting the results. This helped me understand the practical difference between an O(n) search and the average O(log n) search time of a reasonably balanced BST. A basic BST is not self-balancing, though, so its performance can decline if the tree becomes one-sided.</p>

<p>One challenge I encountered was a NullPointerException in my in-order traversal method. The recursive method continued until it reached a null node, but I had not handled that case correctly. I fixed it by adding a base case that returns when the node is null. This reminded me how important it is to test edge cases, especially when working with recursive methods. I also learned that replacing a data structure affects more than storage. I had to update the service classes and verify that searching, deleting, and the existing functionality still worked correctly.</p>

<p>The feedback I received on the project was positive, and I was told that I did not need to make additional changes. I still tested the enhancement and measured its performance so I could verify the results myself. That process reinforced the importance of checking my work rather than assuming a change is successful simply because the code compiles.</p>

<p>This enhancement helped me apply data structures and algorithms to improve the efficiency of an existing application. By replacing the ArrayList with a binary search tree, I was able to reduce search time while keeping the application's functionality intact. I also applied what I learned about data structures in an earlier course to a Java project and used JUnit testing to verify that the changes worked correctly. Comparing the performance of both approaches gave me measurable evidence of the improvement and helped me better understand how technical decisions affect an application's performance.</p>

## Databases

<p>
<a href="https://github.com/briepeno/briepeno.github.io/tree/main/AnimalShelterDashboard_README">
  Animal Shelter Dashboard Project
</a></p>

<p>For my database enhancement, I selected the animal shelter dashboard I originally developed in CS 340: Client/Server Development. The application was built using Python and MongoDB and allowed users to search animal shelter records, view the results in a table, and explore the information through a chart and interactive map. I chose this artifact because it gave me an opportunity to expand on a project I had already completed while demonstrating my skills in database management, Python programming, and application development.</p>

<p>The biggest change I made was expanding the dashboard into a full CRUD application. Although the original Python module supported database operations, users could only search and view records through the dashboard. For my enhancement, I added separate tabs for creating, reading, updating, and deleting records. I also introduced user authentication so that users could search records without logging in, but needed authorization to make changes. I used bcrypt to hash passwords and added checks to prevent duplicate usernames. These improvements allowed me to work with both the database and the application interface while considering how to control access to stored information.</p>

<p>Another area I focused on was improving how the application handled data. I added fields for date of birth, record date, and record time, along with automatic calculations for age-related information. One challenge was making sure new and updated records followed the same structure as the existing MongoDB documents. MongoDB does not require every document to have identical fields, but inconsistent records can create problems when searching, updating, or displaying information. I had to consider which values should be entered by the user, which could be calculated automatically, and how to handle missing information. Working through these decisions helped me better understand the importance of data consistency and validation, even when using a flexible database structure.</p>

<p>I also made changes to the dashboard's visualizations and layout. I replaced the original pie chart with a bar chart because I thought it would make comparisons between categories easier to understand. I kept the interactive map and reorganized the dashboard to reduce scrolling and make the different functions more accessible. One thing I learned was that making changes to the database was only part of the process. I also needed to make sure those changes appeared correctly in the dashboard. This required me to consider how the database queries, application logic, and visualizations worked together.</p>

<p>Testing was an important part of this enhancement because I was adding several features to an application that originally focused on displaying information. I tested the create, update, and delete functions to make sure changes were reflected in MongoDB. I also checked how the application handled different inputs and whether the new fields displayed correctly. As I worked through these issues, I made adjustments to the forms, validation, and interface. Much of the feedback I incorporated came from reviewing the application as I tested it and identifying areas that were confusing or did not behave as expected. This helped me recognize problems that were not obvious when looking at the code alone.</p>

<p>This enhancement addressed the course outcomes related to designing and evaluating computing solutions, using appropriate tools and techniques, and considering security during development. I demonstrated these skills by expanding the MongoDB CRUD operations, improving how records were validated and managed, and implementing authentication for database modifications. I also applied Python, PyMongo, Pandas, and Dash to connect the database to an interactive interface. Although I improved security through password hashing and access controls, the MongoDB connection credentials are still stored directly in the CRUD module. This is an area I would handle differently in a production application, where credentials should be stored separately from the source code.</p>

<p>Overall, this project helped me develop a better understanding of how database design affects the rest of an application. I learned that adding CRUD functionality involves more than writing database queries. The interface needs to collect the correct information, the application needs to validate it, and the database needs to store it in a way that remains consistent and useful. The enhanced dashboard is more functional than the original version, and the experience gave me more confidence working with MongoDB, Python, and database-driven applications.</p>
